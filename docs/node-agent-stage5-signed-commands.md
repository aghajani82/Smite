# Stage 5 — Strict HMAC Agent API gate (INERT BY DEFAULT)

**DRAFT ONLY. Nothing has been installed on IR/KH. Do not enable strict
mode on any live Node until the Panel NodeClient is upgraded and tested.**

This branch is stacked after Smite drafts #2 (HMAC), #3 (encrypted/atomic
pairing store), #4 (HTTPS pairing endpoints), #5 (admin UI). The paired
identity wizard is still in separate U-OPTI draft #29.

## New behavior when explicitly enabled on a Node

- `node/app/agent_auth.py` implements the opt-in request guard for
  **all four endpoints** under `/api/agent`: status, tunnels/status,
  tunnels/apply, tunnels/remove. Guard is installed as a FastAPI router
  dependency, so there is no unprotected sibling action.
- Node identity is loaded from a private file: root/current-service-user
  owned `0600`, inside a `0700` directory. No JSON credential leaks
  through status or Python logs. Unconfigured / invalid file -> 503.
- Uses `node_auth.verify_request` from Stage 1: signed node UUID, HTTP
  method, exact raw path and query, raw request body SHA-256 digest,
  timestamp (±90 seconds), fresh 128-bit nonce and HMAC-SHA256 key.
- Replay store is a private SQLite database with `BEGIN IMMEDIATE`,
  atomic unique nonce insert and a bounded capacity; replay is rejected
  across concurrent workers and **restarts** as long as the database is
  on persistent storage. Storage unavailable -> 503, no memory fallback.
- Bad/missing/stale/tampered signature -> 401 before adapter calls.
- Request size capped at 1 MiB in strict mode.
- Default `SMITE_AGENT_AUTH_MODE=legacy` (controlled Literal enum)
  preserves current deployment. Note that `legacy` is **not secure**.

## Panel sender preparation

`panel/app/agent_request_signer.py` creates HMAC-signed exact raw JSON
POST bodies for Apply/Remove and signed GET status, using the same shared
cryptographic module. Caller must send the generated byte body without
reformatting via `httpx(..., content=body, headers=headers)`.
It is **NOT YET WIRED** to live `NodeClient`; no runtime Panel calls
were changed. Verified TLS transport and the node secret lookup still
require a separate coordinated PR. The prototype avoids accepting arbitrary
URLs or signing unrelated endpoints.

## Strict mode activation holds

1. An authenticated, reviewed enrollment workflow must have provisioned
   matching UUID and key on Panel and Node; Node container must receive the
   credential via read-only mount. Do not expose it in Compose `environment`.
2. Durable replay directory must be root/service-owned mode `0700`,
   containing mode-`0600` SQLite database on persistent storage. The
   current Node image is **not configured** to mount or prepare this path.
3. Panel NodeClient must get key from internal encrypted DB, sign
   status/apply/remove calls on the exact transmitted bytes and use
   **certificate-verified TLS** for the public 443 gateway. Current
   `verify=False` legacy client is a blocker.
4. Reverse-proxy path rewriting and the 443 gateway must preserve the
   signed `/api/agent/` target; Nginx must never send the identity
   secret in a request header to public clients.
5. Node→Panel registration and FRP status are still anonymous and need a
   separate signed transition. Parent Panel Node list/delete require
   admin authorization compatible with existing U-OPTI gateway discovery.
6. IR and KH must be snapshotted and upgraded in a controlled window with
   a rollback design. Verify FRP and Backhaul actual client traffic,
   liveness, key revocation, invalid code, wrong key and reboot.
7. Private Network mode must not be forced onto Standard-only localhost
   paths; coordinate its own control transport before enforcing.

## Security limitations

HMAC protects *authenticity/integrity*, not payload confidentiality. It is
not a replacement for verified TLS and a restricted HTTPS/443 ingress.
The current legacy mode remains unauthenticated. This PR is NOT production
security completion and must not be deployed to main as a completed feature.

## Offline CI

`tests/test_node_agent_signed_commands.py` exercises signed Agent status,
Apply/Remove, replay (including simulated restart), forged/expired/
tampered signatures, storage permissions and concurrency, and verifies
legacy mode unchanged. No live servers/containers/tunnels touched.
